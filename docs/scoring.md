# 评分系统

skill-audit 为每次扫描生成 0-100 的安全评分，帮助快速判断 skill 的安全状况。

## 评分算法

```
score = max(0, 100 - dangerCount × 15 - warnCount × 5)
```

| 发现类型 | 每条扣分 |
|----------|----------|
| 🔴 danger | -15 分 |
| 🟡 warn | -5 分 |

- 起始分数：100 分
- 最低分数：0 分（不会出现负分）
- 每个 finding 独立扣分，不去重

### 计算示例

| 场景 | danger | warn | 扣分 | 最终分数 |
|------|--------|------|------|----------|
| 完美 skill | 0 | 0 | 0 | 100 |
| 小问题 | 0 | 2 | 10 | 90 |
| 中等风险 | 2 | 3 | 45 | 55 |
| 高风险 | 4 | 5 | 85 | 15 |
| 极度危险 | 7+ | 任意 | 100+ | 0 |

## 安全等级

| 等级 | 分数范围 | 含义 | 建议 |
|------|----------|------|------|
| A | 90-100 | 优秀 | 几乎没有安全问题，可以放心使用 |
| B | 70-89 | 良好 | 有少量问题需关注，整体安全 |
| C | 50-69 | 一般 | 存在明显安全隐患，建议修复后使用 |
| D | 30-49 | 较差 | 多个安全问题需修复，谨慎使用 |
| F | 0-29 | 危险 | 严重安全风险，不建议使用 |

## 终端显示

```
  Security Score
  ███████████░░░░░░░░░  55/100  Grade: C
  Deductions: 2 danger (-30)  3 warn (-15)
```

## JSON 输出

```bash
skill-audit ./my-skill --json | jq .score
```

```json
{
  "score": 55,
  "grade": "C",
  "breakdown": {
    "danger": { "count": 2, "deduction": 30 },
    "warn": { "count": 3, "deduction": 15 },
    "totalDeduction": 45
  }
}
```

## 如何提高分数

### 快速提升（每条 +15 分）

修复 danger 级别的 finding：

1. **移除硬编码密钥** → 改用环境变量
2. **移除 eval()/exec()** → 使用安全替代方案
3. **移除 curl | bash** → 先下载验证再执行
4. **移除 prompt injection 模式** → 清理指令内容
5. **修复 typosquatting** → 使用正确的包名

### 稳步提升（每条 +5 分）

修复 warn 级别的 finding：

1. **固定依赖版本** → 使用确切版本号
2. **声明权限** → 在 manifest 中声明实际使用的权限
3. **使用安全临时文件** → 用 `mkstemp`/`tempfile` 替代硬编码 `/tmp/`
4. **移除不必要的 POST 请求** → 审计网络调用
5. **审查 Bearer token** → 移至环境变量

### 最佳实践

- 在 CI/CD 中集成 skill-audit，设置分数阈值
- 使用 `--json` 输出追踪分数变化趋势
- 使用 [Diff 功能](../README.md#diff--对比扫描) 对比修复前后的变化
- 目标：保持 A 级（90+）
